# 系统与解调原理详解

突发干扰定点模型标识：`00070001`。本文结合 RTL、实现报告及实测统计说明系统原理。

## 1. 项目解决什么问题

系统在 EGO1 / XC7A35T 上生成 DDS 波形和二进制 FSK，经板载 DAC0832、LM324、J2 模拟输出，再由外接 AD7606 采样。FPGA 对同一组接收样本进行传统判决和 AI 判决，上位机只配置和显示，不承担在线神经网络推理。

当前优化的问题很具体：同步已成功，某些符号受到短时间、高幅度单音干扰，如何减少帧体的判决错误。它不等于提升所有噪声条件下的帧捕获能力，也不是增加信道编码。

```text
DDS / FSK -> 数字叠加干扰 -> DAC0832 / LM324 -> J2
                                                   |
                                              AD7606 AIN1
                                                   |
                                       SPI -> 采样缓存 -> 共享接收前端
                                                   |
                                  捕获 / 频偏 / 定时 / DC / AGC
                                                   |
                                      同一个500点符号窗口
                                        /                  \
                              整窗双频正交相关        10个相关能量特征
                                     |                       |
                                 P1 > P0                定点小网络
                                     |                       |
                               传统比特序列              AI比特序列
                                        \                  /
                                       独立CRC / BER / 帧统计
                                                   |
                                             UART -> GUI / CSV
```

“双支路”表示保留两种判决及各自统计，不意味着复制两套 ADC、缓存和同步电路。当前硬件按状态机分时执行，传统判决与 AI 判决来自相同窗口。共享同步使本实验更适合比较载荷判决，不适合声称 AI 独立同步更强。

## 2. 时间、频率与帧格式

| 项目 | 当前值 |
|---|---:|
| FPGA 系统时钟 | 100 MHz |
| DAC 更新率 | 100 kSPS |
| ADC 有效采样率 | 50 kSPS |
| 符号率 | 100 bit/s |
| 一个符号 | 10 ms |
| DAC 每符号样本 | 1000 |
| ADC 每符号样本 | 500 |
| 比特 0 / 1 的标称载波 | 1000 Hz / 2000 Hz |

DDS 的频率控制字为 `round(fout × 2^32 / 100000)`。分母是 DDS 实际采样使能频率，不是 100 MHz 系统时钟。

一个空中帧为 384 bit：

| 字段 | 空中位索引 | 长度 | 用途 |
|---|---|---:|---|
| 低频前导 | 0..15 | 16 | 连续 0 |
| 高频前导 | 16..31 | 16 | 连续 1 |
| 交替前导 | 32..63 | 32 | 符号定时评分 |
| 同步字 | 64..95 | 32 | `0x1ACFFC1D`，高位先发 |
| 帧 ID | 96..111 | 16 | 帧编号 |
| 载荷 | 112..367 | 256 | PRBS15，逐帧种子 1 |
| CRC | 368..383 | 16 | CRC-16，覆盖 ID 和载荷 |

帧本身约 3.84 秒，默认帧间隔约 0.2 秒，因此 100 帧约需 404 秒，再加启动和报告等待时间。CRC 多项式为 `0x1021`、初值 `0xFFFF`。CRC 用来检测错误，不纠正错误。

## 3. 接收前端：两条支路共同的基础

### 3.1 ADC 与缓存

`src/rtl/ad7606_spi_rx.sv` 在 50 kSPS 节拍下触发转换，等待 BUSY 先高后低，再读出 128 位串行数据，提取 AIN1 的 16 位有符号样本。完整事务成功后才产生有效样本。异常恢复和削顶另有计数。

`src/rtl/fsk_receiver.sv` 将样本写入 65536×16 bit 的环形缓存。容量为 128 KiB，约能保存 1.31 秒原始样本。接收机按需要回放前导段和当前符号，采样写入持续进行。缓存不是保存整段 100 帧数据的存储器。

### 3.2 捕获

当前搜索主窗为 500 点，每次推进 100 点；搜索阶段探测多个共同频偏，使用低频连续段及随后高频段定位前导过渡，同时有能量和单音特性门限。接收边界由 ADC 数据产生，不把发送端 bit_index 接入判决器作为同步答案。

这里必须区分两种失败：没有建立同步或没能收到完整帧，会体现为 lost；同步已建立但载荷判错，会体现为 BER 和 CRC 失败。一个支路 BER 为零而 lost 很高，并不能称为高可靠接收。

### 3.3 频偏、直流与定时

接收机回放两个稳定前导段，每段 4096 点，以 `-100:10:+100 Hz` 共 21 个候选搜索共同频偏，使用期望载波相关功率评分。原始样本和用于估算 DC。

符号定时使用 32 bit 交替段：先在过渡估计附近 ±350 个 ADC 样本范围内按 25 点粗搜，再在最佳点附近 ±24 点逐点细搜。评分本质上是期望频率能量减非期望频率能量的累加。

同步字最多容忍 2 bit 不匹配。同步失败返回搜索；每帧重新捕获。频偏、DC、AGC 在载荷阶段保持冻结，避免两支路因各自更新前端而失去公平对照。

### 3.4 幅度归一化

相关前先扣除 DC，再使用 `2^gain` 的移位增益，并进行饱和和右移。AGC 指数不是电压值。数字放大只能调整可表示的样本幅度，不能恢复 ADC 或 DAC 已削顶的信息。

## 4. 传统解调：双频正交相关能量判决

核心实现为 `src/rtl/fsk_correlator.sv`。对同一个 500 点符号窗口分别使用两个参考频率，每个频率有正弦、余弦两条正交相关支路：

```text
Ik = sum(x[n] * cos(2*pi*fk*n/Fs))
Qk = sum(x[n] * sin(2*pi*fk*n/Fs))
Pk = Ik^2 + Qk^2, k = 0, 1
decision = 1 if P1 > P0 else 0
```

正交能量形式减轻了未知载波相位的影响。RTL 使用 24 位 NCO、256 项正弦表、整数乘加；累加结果先右移 8 位再平方，功率用 64 位表示，具体缩放以 RTL 为准。

为什么整窗相关平时很好用？期望载波在一整位内相干累积，随机噪声较难持续同相累积。理想正交、同步正确且以加性白噪声为主时，这类检测器是很强的基线，不能预设神经网络一定更优。

为什么强突发单音会造成错误？干扰的频率可能接近另一个载波，虽然只持续四分之一位，却因幅度较大在相关累加中形成很大贡献。整窗判决最后只看到两个功率，难以区分“真正持续整位的载波”和“很强但短时出现的载波”。

例子：真实发送 2000 Hz，即比特 1；在某一小段混入很强的 1050 Hz 单音，可能抬高 1000 Hz 相关功率，使 P0 超过 P1。它不是 UART 丢包，也不一定是 ADC 接口故障。

## 5. AI 解调：利用时间分布的定点分类器

### 5.1 输入不是原始 500 点波形

当前 AI 使用 10 个 int16 特征，与传统判决共享相关运算：

| 特征索引 | 内容 |
|---|---|
| 0、1 | 第 0 个 125 点子窗的低/高频功率 |
| 2、3 | 第 1 个子窗的低/高频功率 |
| 4、5 | 第 2 个子窗的低/高频功率 |
| 6、7 | 第 3 个子窗的低/高频功率 |
| 8、9 | 完整 500 点窗的低/高频相干功率 |

子窗功率右移 14 位、整窗功率右移 18 位，限制到 0..32767。整窗相干功率一般不等于四个子窗功率之和，后者丢掉了跨子窗的相位关系；因此保留两种特征。

特征提供了传统最终判决没有直接使用的“能量何时出现”信息。网络可以利用某一子窗异常、其他子窗一致等模式。这里只能说模型可能学到此类规律；没有逐神经元解释实验，不能把直觉当成已证明的内部机制。

### 5.2 结构与定点计算

`src/rtl/ai_mlp.sv` 实现 10→16→8→2 的全连接网络：

```text
h1 = sat16(ReLU((W1*x + b1) >> 4))
h2 = sat16(ReLU((W2*h1 + b2) >> 5))
z  = W3*h2 + b3
decision = 1 if z1 > z0 else 0
```

权重按 int8 范围训练和导出，输入及隐藏激活为 int16，参考模型使用 int32 累加范围检查。ROM 为方便索引按 32 位字保存参数，不能把“330 参数”误说成整个模型只有 330 字节。

参数数目为 `10×16+16 + 16×8+8 + 8×2+2 = 330`，其中 304 个权重、26 个偏置。共 304 次乘加，两周期完成一次乘积与累加，加上控制和激活状态后约为数微秒量级，远小于 10 ms 的符号时间。资源报告中推理模块使用一个 DSP，复用执行，不是给每个权重安排一个 DSP。

输出比较两个整数 logit，不计算 Softmax。这样可避免在 FPGA 上实现指数和除法。模型是离线监督训练、在线固定权重推理；上板测试不会自动学习或更新参数。

### 5.3 训练与独立测试

`build/scripts/burst_experiment.py` 生成训练样本，通过 NumPy 做量化感知训练，固定移位 `(4,5,0)`。训练随机种子 71001，验证种子 72001，在三个训练初始化中按验证误差选模型。测试种子 73001/74001/75001 不用于选择模型。

符号样本包含随机数据、相位、幅度和频偏；训练干扰频率 1000/1050/1950/2000 Hz，相对幅度 0/3/4/5。每个符号约一半概率在随机一个子窗加入干扰。另有未参与上述频率集合的 1020/1100/1850/1980 Hz 测试，以及随机帧体、重新计算 CRC 的完整帧测试，避免只记住固定 PRBS 序列。

导出前核对完整帧证据与候选权重指纹。`src/ai/model.py` 为整数参考，`sim/ai_golden.txt` 和 `tb_ai_mlp` 检查 RTL 与整数计算的一致性。训练得到浮点精度好，不代表定点 RTL 已正确，因此这两类检查不可相互替代。

## 6. 指定突发干扰的定义与公平性

Payload burst 在前 96 个空中符号内关闭干扰，随后 ID、载荷和 CRC 都允许受扰。帧体内每个 10 ms 符号约有 50% 概率，在随机一个 2.5 ms 子段注入单音。正弦干扰相位连续运行，伪随机门控与载荷 PRBS 使用不同来源。

发送端知道自身位索引，用于控制实验干扰何时开始；这一索引没有送到接收判决器。发送结束信号只参与 lost 评价，config/run 只用于统计归组，不提供期望比特或接收窗口边界。

两支路使用相同样本、同步、频偏和增益，统计各自的 ID、载荷、CRC。AI 网络输入只有 10 个能量特征，没有输入 PRBS 参考比特。已知 PRBS 仅用于判决之后评价 errors。

这种实验是对“成功同步后的短时干扰鲁棒性”的受控比较。它不能证明在前导也被同样强烈干扰时还能成功捕获，更不能推广成任意电磁干扰环境下的优势。

## 7. BER、CRC、捕获和丢帧分别说明什么

| 指标 | 工程中的含义 | 注意点 |
|---|---|---|
| Payload BER | 载荷错位数 / 已解调载荷位数 | CRC 失败的完整捕获帧仍计入 |
| Errors / bits | 原始载荷错误数和分母 | 便于核对，通常每完整帧 256 bit |
| CRC failures | 接收 CRC 与本支路计算 CRC 不符的帧数 | 不等于错误比特数 |
| Captured frames | 已完成接收处理的帧 | 包括 CRC 错误帧 |
| Lost frames | 评价等待期内没有完成捕获的帧 | 不进入 BER 分母，不能忽略 |
| ADC errors | 接收事务等异常计数 | 与载荷判错分开看 |
| ADC/DAC clips | 近满量程采样或数字削顶计数 | 数字 AGC 无法恢复削顶信息 |
| Dropped reports | 历史报告队列丢失 | 非零时对照证据不完整 |
| Final incomplete | 等待接收结果超时或不完整 | 不应作为完整验收结果 |

零错误只说明有限样本中未观测到错误，不等于真实 BER 永远为零。GUI 采用约 `3/N` 的零误码 95% 单侧上界；这是独立同分布近似，突发误码存在相关性时不能当作严格信道保证。

## 8. 已有证据与硬件开销

| 测试 | 传统错误 | AI 错误 | 证据性质 |
|---|---:|---:|---|
| 完整帧 96/96 捕获，24576 bit | 2173 | 0 | Python 接收仿真 |
| 真实 RTL 发射→理想 ADC 映射→RTL 接收，256 bit | 30 | 0 | 数字仿真 |
| 前者 CRC 失败帧 | 47 | 0 | 同一完整帧仿真 |

已有 24 项 RTL 仿真日志。最终 bitstream 由 Vivado 2026.1 生成，100 MHz 下 WNS 0.000 ns、WHS +0.038 ns、TNS/THS 为零，DRC 无错误及严重警告。setup 余量很紧，改动后必须重新验证。

| 资源 | 整机 |
|---|---:|
| LUT | 12945 |
| FF | 10747 |
| RAMB36 / RAMB18 | 35 / 9 |
| DSP | 21 |

AI 推理模块自身为 406 LUT、276 FF、1 DSP、无块 RAM。共享相关器为 684 LUT、589 FF、16 DSP、2 RAMB18。推理模块的开销不包含采样、同步与特征提取，不能当成独立 AI 接收机的总开销。

模拟回环实测结论见 `report/design_report.pdf` 3.3 节为准：1050 Hz 突发干扰的 100 帧 Final 为传统 4061/25600、AI 0/25600，两路均捕获 100 帧、丢帧为 0；1900 Hz 的 200 帧 Live 与持续干扰退化实验分别记录。实测与软件/RTL 仿真分开统计；证据索引见 `data/hardware_results.json`。

## 9. 局限与可以怎样表述成果

简单的“四子窗多数判决”在当前选定测试中同样零错误，因此结果证明的是相对于现有整窗传统基线的改善，不能说只有 AI 能解决。

1020 Hz 持续单音、100 帧 Final 的实际模拟回环中，传统载荷为 0/25600 错误，AI 为 4443/25600。网络重点适配局部突发，保留传统支路可展示不同信道下的适用范围。

可以表述为：在前导和同步受保护、指定短时单音干扰条件下，以小规模定点网络和有限整机增量，提高相对于现有整窗传统支路的载荷解调可靠性，并保留同源实时对照。上板效果还受模拟带宽、滤波、延迟和削顶影响，需要重复试验给出最终量化结果。

## 10. 源码阅读顺序

1. `src/rtl/fsk_frame_tx.sv`：一帧如何产生、PRBS 和 CRC 如何更新。
2. `src/rtl/sample_path.sv`、`src/rtl/tone_jammer.sv`：幅度、偏置、噪声和突发门控。
3. `src/rtl/ad7606_spi_rx.sv`：有效样本怎样进入 FPGA。
4. `src/rtl/fsk_receiver.sv`：SEARCH→频偏→TIMING→SYNC→DATA→AI_WAIT→发布。
5. `src/rtl/fsk_correlator.sv`：功率公式、子窗和整窗 10 维特征。
6. `src/rtl/ai_mlp.sv` 与 `src/ai/model.py`：每一层的定点算术和两周期 MAC。
7. `src/rtl/statistics.sv`、`src/rtl/report_history.sv`：运行分组、旧结果排空和最终报告。
8. `src/host/protocol.py`、`src/host/client.py`、`src/host/gui.py`：解包、串口线程和展示。

建议先手算一次 `P1>P0`，再对照一个黄金向量验证第一层整数结果，最后解释一帧的 errors/bits、CRC 和 lost，避免只会引用最终 BER 数字。
