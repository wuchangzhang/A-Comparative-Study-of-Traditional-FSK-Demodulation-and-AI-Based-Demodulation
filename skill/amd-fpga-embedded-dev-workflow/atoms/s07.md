# S07 diagnose

先读 [公共契约](../runtime-contract.md)。职责：依据证据分类和定位，不自行改码或运行开发工具。

输入：`logs:object[]`、`report_paths:string[]`、`evidence_paths:string[]` 至少一个非空。可选 `failure_context:object`、`input_manifest:string`。

前置：诊断硬件、引脚、连接器、供电或模拟链时，preflight 必须包含实际板卡/revision、原理图、当前 XDC/pin mapping、接线与仪器条件。先通过 Vivado AI MCP 查询可用硬件资料；MCP 无资料时请求用户提供并返回 2，不转用互联网，也不把通用板卡知识当作本板证据。

流程：确认实际输入/工具/失败阶段，保留原始错误，区分 lint/elaboration、RTL、tb、HLS、AIE、IP/Block Design、约束、工程配置、工具环境、下载、数字信号、DAC 模拟链及仪器设置。候选原因必须含证据位置、推断依据、验证动作和不确定项，不能把猜测写成根因。时序问题先将 routed critical path 映射回 RTL/HLS；J2 故障先核对实际下载版本、地/耦合、控制与数据活动，再分析模拟电路。

输出：`issue_class:string`、`candidates:object[]`、`repair_target:string`（S01/S03/S09/none）、`regression_scope:string[]`、`unresolved:object[]`。

区分“设计失败”“报告/Tcl 兼容失败”和“归档失败”。路由已完成但报告参数报错，或 PowerShell JSON 序列化内存溢出，都不证明 RTL 失败。保留报错脚本、日志和当前 checkpoint，按 [修复与续跑](../references/timing-recovery.md) 提出恢复条件；不因诊断成功自动重跑工具。

成功判据：可追溯的诊断与下一步明确；根因不明时允许输出待取证，不虚构确定性。默认 60s。只有调用链原失败码为 4 才允许自动进入修复；2/3/5/6 不借本 atom 绕过终止规则。
