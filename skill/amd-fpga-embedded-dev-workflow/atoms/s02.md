# S02 plan-gen

先读 [公共契约](../runtime-contract.md)。职责：将请求变成有边界和验收依据的计划。

输入：`requirements:object`，至少含 `goal:string`、`scope:string`、`track:string`、`target_platform:string`、`tool_release:string`、`features:object[]`、`constraints:object`、`available_evidence:string[]`、`acceptance_goals:object[]`。每个 feature 包含目标、优先级、已实现状态及验收方法；影响方案成立的未知项必须先向用户提问，不猜数值。

流程：先对 requirements 执行 preflight；目标、范围、目标平台、主要功能、硬约束或验收目标不完整时返回 2，逐项提问，不生成貌似完整的方案。输入足够后，采用用户声明的赛道、Vivado/Vitis 版本和目标平台；读取已有方案和当前执行计划，明确冲突及本次范围，优先复用实际工程。区分基础 RTL/DDS/DAC、HLS、FSK、AIE/Versal 和选定扩展，列假设、接口、负责人、依赖、所需硬件资料、阻塞项及停止条件。可对尚未确定的非关键阈值给出有来源的候选值，但必须标为待用户确认；确认前不执行依赖步骤。

输出：`plan_path:string`、`tech_route_path:string`、`acceptance_path:string`、`open_items:object[]`。

成功判据：计划、路线与验收矩阵相互对应，所需工程输入和硬件资料清单完整，未执行的项目均标为待执行。输出方案必须由用户确认后才可作为 S01 及后续执行 atom 的 `approved_plan`；写计划不证明功能完成。默认 30s，公共退出码适用。
