# S03 code-gen

先读 [公共契约](../runtime-contract.md)。职责：按明确规格小范围修改 RTL、XDC、tb、HLS C/C++、AIE kernel 或 host，不执行验证工具。

输入：`module_spec:object[]`、`write_allowlist:string[]`。每项 spec 至少含 `path:string`、`purpose:string`、`interfaces:object`、`acceptance_checks:string[]`。修复时另需 `diagnosis_evidence:string[]`。

前置：module_spec、影响范围、验收检查和写入白名单须完整；涉及板级接口、XDC、IP 或平台配置时，preflight 还必须绑定适用的手册、原理图和当前约束依据。资料缺失时返回 2，只提出资料请求，不写文件。

流程：先审阅真实模块、调用方与板级依据，确认位宽/符号、时钟复位、接口和初始化依赖；HLS 另核对 top function/pragma/接口协议，AIE 另核对 API、内存 bank 和平台边界。硬件依据先由 Vivado AI MCP 查询；MCP 无结果时只能请求用户提供，不自行联网。写前保存完整快照，严格在 allowlist 内修改，使用仓库既有风格，不改无关代码。修改测试不能弱化原验收，参考结果的变化需有独立依据。

输出：`written_files:string[]`、`snapshot_path:string`、`diff_path:string`、`impact:object`、`invalidated_evidence:string[]`。

差异采用可应用的 unified diff，并保留原字节及修复后哈希；PowerShell `Compare-Object` 展示表不能当作补丁。时序流水化先核对周期、valid/enable、非阻塞赋值、复位、位宽及 signed/truncation 语义，见 [修复与续跑](../references/timing-recovery.md)。

成功判据：变更符合规格、快照和差异完整、需回归项明确；此处成功只表示写入完成。默认 60s，公共退出码适用。后续验证由显式路由到 S04/S05 完成。
