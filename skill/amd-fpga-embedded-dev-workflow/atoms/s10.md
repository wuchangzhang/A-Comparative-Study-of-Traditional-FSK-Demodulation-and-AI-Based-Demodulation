# S10 release-pack

先读 [公共契约](../runtime-contract.md)。职责：在离线副本中审计和打包已存在的成果，不隐式执行开发流程或发布到外部平台。

输入：`release_spec:object`、`evidence_paths:string[]`。release_spec 含 `release_id:string`、`mode:string`（draft/final）、`source_manifest:string`、`required_checks:string[]`、`destination:string`，以及所选功能、工具版本、器件/平台和自主选题初级组声明。

流程：先审计 preflight、已确认方案及其工程/硬件资料清单；检查源码/约束/ROM/IP/HLS/AIE/构建脚本齐全，仿真、综合、实现、下载、实测证据与选定版本一致。硬件资料缺失必须列入 missing_items，不得用仿真 PASS、bitstream、下载日志或截图替代。核对黄金参考、原始数据、优化前后条件、时序/方法学/资源报告、大模型提示词/回答/纠错记录、Skill 用法/边界/验证来源、许可证和复现步骤。检查提交副本的英文文件名与相对路径；保留 README.md、SKILL.md 等标准入口命名。推荐映射 src/hls/aie/sim/build/board/data/skill/report，其他组织提供映射表。

从零重建记录是独立证据；没有则列为 missing，不为了补齐而自动启动 S04/S05。需要重建时另发明确任务并走正常准入链。材料中的计划与待测项不能变成已完成结论。缺少优化、跨项目复用等证据时明确列缺口，不虚构收益。

交付必须有一个顶层 `reproduction.md` 和一个明确指向的当前状态 JSON。恢复执行后，更新入口以指向最新已完成 attempt；早期 blocked/failed 状态放入标注为历史的记录，不得与当前状态混用。并行修复属于独立输入及 attempt，未验证前不覆盖原结果。

可重放命令逐项记录扁平字符串数组 `argv`、`cwd`、实际返回值及日志路径/哈希；不得用嵌套数组、空对象或展示用字符串代替真实参数。事后从脚本重建的参数明确标为 reconstructed，保留原始记录。复现入口应指定稳定脚本、工具版本、环境、调用顺序和全部参数；废弃脚本保留为历史证据但不得继续作为推荐入口。

归档后修改说明或状态时，保留旧包及旧清单，用新清单与补充包绑定修改；不得改写旧哈希冒充原执行证据。重放命令应使用独立副本和新输出目录，避免写入并行修复现场。

归档辅助脚本放在本次输出目录。日志停止变化后逐文件哈希；大目录用 [流式清单](../references/timing-recovery.md)，不序列化整个 FileInfo/进程对象树。校验 ZIP 成员与冻结清单的哈希、全包 CRC 和包外 ZIP 哈希，分别记录覆盖范围。仅核对 12 个关键文件不能称全包完整性通过。复现命令明确使用修复后副本，或先校验原版哈希并应用登记补丁；不能只复制未修复原版就声称重现修复结果。

输出：`package_path:string|null`、`manifest_path:string`、`missing_items:object[]`、`submission_ready:boolean`。清单含文件哈希、来源 run_id、对应验收项、状态和复现环境。

成功判据：draft 可在列出缺失项后返回 0，但 submission_ready=false；final 必须全部 required_checks 有效通过，缺失输入返回 2、证据表明功能失败返回 4，不标正式就绪。默认 120s，公共契约适用。公开仓库发布不属于本 atom，须遵守用户单独授权范围。
