# S04 simulate

先读 [公共契约](../runtime-contract.md)。职责：在固定输入快照上进行自检仿真。

输入：`testbenches:string[]`、`sim_mode:string`（behavioral/gate/timing；适配器未验证的模式返回 3）、`input_manifest:string`、`tool_adapter:object`、`test_config:object`（含每个测试的顶层、运行上限、结束条件与断言/黄金参考判据）。

流程：确认项目声明的 Vivado/Vitis HLS/AIE 版本与实际适配器；每次先探测 MCP 仿真能力，不可用再调用同版本 XSIM、HLS cosim 或 AIE 仿真工具。顺序记录编译、展开、运行及自检结果。检查本次相关的接口协议、复位、样本使能、ROM/权重加载、FCW、DAC 时序或 kernel golden reference。退出码 0、出现 PASS 字样或跑满时间均不能单独认定通过；必须正常结束且全部必选判据通过。

输出：`passed:string[]`、`failed:string[]`、`simulation_evidence:string`、`stage_results:object[]`。证据含输入哈希、测试配置、实际工具版本、原始日志与逐项结果。

离线辅助：按 [使用说明](../references/usage.md) 在运行前后调用 `workflow.py verify`；已确认的批处理命令可用 `run` 留证。该助手的退出码 0 只代表命令正常退出，必须另行核验本 atom 的逐项测试判据，不能直接作为 `simulation_evidence` 放行 S05。

时序修复先运行受影响测试，再执行验收要求的完整回归；两者都绑定修复后固定输入。波形采集按故障窗口和必要信号限量，记录未采集范围，不以减少波形为由跳过判据；日志与产物清单分开，避免把持续写入的 results 纳入输入基线。

调用前识别驱动脚本解释器：Python 仿真驱动不传给 Vivado `-source`，Tcl 参数按当前版本接口传入，不照搬 `--`。完整原始日志的检查见 [命令调用](../references/timing-recovery.md)。

成功判据：所有必选测试通过、输入未变化、无未解释的 fatal/error。设计/测试失败返回 4，输入/环境问题按公共契约处理。异步默认总时限 3600s；实际作业超时返回 5，不自动解释为设计失败。未成功禁止 S05。
