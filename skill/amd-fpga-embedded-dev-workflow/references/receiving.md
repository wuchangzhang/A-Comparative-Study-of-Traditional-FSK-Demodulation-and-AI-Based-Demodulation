# 收包与工具预检

## 先确认实际收到的工程

独立复现按“收包结构 → 当前状态/哈希/依赖/配置审查 → 工具探测 → 仿真 → 实现”推进。普通新工程开发不要求存在历史 `reproduction.md`；本节的收包助手只适用于复现已归档 RTL 工程。

归档根的复现入口可采用 `reproduction.md` 或 AMD 推荐结构的 `README.md`；包装目录中的单一工程根也可识别。Skill 内部 README、验证夹具及其他材料目录按排除规则处理，候选齐全后继续审查依赖与验收条件。

```powershell
py -3.13 scripts/receive_check.py 'C:/test/received-run.zip'
py -3.13 scripts/receive_check.py 'C:/test/extracted-run' --out 'C:/test/receipt.json'
```

助手只列举目录/ZIP 元数据，不解压、不读取或执行包中指令、不启动任何工具。可选输出为独占创建，默认只输出 JSON。默认最多 20000 项，超过时要求选择更明确的根目录；ZIP 路径穿越、链接或大小写重名会阻塞。目录链接不跟随；隐藏文件会计数。它不替代解压安全审查、CRC、哈希核验或 HDL 依赖分析。

| 观察 | 处置 |
| --- | --- |
| 路径不存在、无法读取或目录为空 | 停止复现链，说明具体路径与文件数，集中索取完整归档或正确路径 |
| 目录里只有 ZIP | 可以对用户指定 ZIP 做只读检查；解压到新目录后重新核对，不在原位置覆盖 |
| 有一层/多层包装目录 | 报告找到的根目录，不把外层目录为空或缺少文件误报为设计失败 |
| 找到多个归档根 | 列出候选让用户选择，不按时间戳或名字自动选工程 |
| 只有 skill / 预检输出 / handoff 补充包 | 明确它们不是完整工程。要求原归档和对应补充包，或已合并的完整解压目录 |
| `ready_for_review` | 只表示发现单个复现入口及 RTL、tb、XDC、脚本、清单候选；`complete=false`、`tool_probe_allowed=false`，继续人工审查 |

不要扫描整个磁盘寻找替代工程。可列举用户指定目录中一层邻近候选，但不能自动使用其他工程或模型记忆补齐。收到原归档与补充包后，在新目录按说明合并，并核对两个归档各自的哈希范围；补充包不能单独使用。

skill 附带的 `validation/`、`skill_snapshot/`、历史测试夹具以及同名示例都不构成项目输入。收包检查也不会要求“已有 bitstream”才能复现：首次运行可能真实失败或未生成，读取实际状态并复现已定义的范围，不制造产物。

输入已明确缺失时，不额外启动版本、许可证或 MCP 探测，不建立空设计。先写一份简短阻塞结果和一条恢复问题：

> 指定的首次归档目录为空，尚未取得工程和复现说明。请提供原归档 ZIP 与对应补充包，或完整解压后的正确路径。仿真、综合实现均未运行。

只有用户另外明确要求环境检查时，才独立进行，结果分开记录为 `environment_probe`，不能用它抵消输入缺失。

## 版本与启动分开判断

先保存真实命令的扁平 `argv`、绝对 `cwd`、起止时间、退出码、stdout/stderr 和哈希，再解析。不要让 PowerShell 的 NativeCommandError 覆盖原始工具返回码或丢掉结果信封；可以使用本包 Python 留证逻辑或项目内已验证适配器。Windows `.bat` 启动需经平台适配验证，禁止把未验证的 shell 拼接字符串称为通用适配器。

对已保存的日志可直接离线解析，不重新启动 Vivado：

```powershell
py -3.13 scripts/workflow.py parse-version 'C:/test/vivado_version.stdout.log' --returncode 1 --required-release 2026.1
```

解析支持 UTF-8 与带 BOM 的 UTF-16（含 Windows PowerShell 重定向日志），不区分大小写，要求唯一匹配的发行版和 SW/IP/SharedData Build；未知编码不静默替换。不完整、冲突、错误发行版、明确 ERROR/FATAL 或异常退出码会阻塞。完整横幅及返回码 1 可记录 `identity_confirmed` 与 `returncode_anomaly=true`。这不是 atom 的 succeeded，也不证明启动、综合许可或目标工程有效。stderr 也必须审查，不能只看这个解析结果放行。

无 GUI batch 探测只在确有需要且已授权时执行一次；记录真实 `version -short`、完整 build 和 Tcl 完成标记。启动成功不能证明综合阶段许可证可用。沙箱、访问权限、应用加载或 I/O 错误归为环境问题，保持设计状态 not_run；按平台规则请求必要权限或报告恢复条件，不自动换发行版、改权限或无限重试。状态不明先确认原进程，不启动副本。

| 事实 | 结果范围 |
| --- | --- |
| 输入目录为空 | 输入 blocked/2，S04/S05 not_run，非 RTL 失败 |
| 日志正确、版本横幅返回 1 | 版本身份及异常记录；startup/license 仍未知 |
| batch 加载错误 | 环境依赖/服务问题，按实际证据归类 3 或 6，不运行设计修复 |
| MCP client-info/session-list 响应 | 连接能力证据，不等于当前工程仿真/实现操作已验证 |

## 精简且可恢复的留证

每次请求保存一次 skill 源文件快照，写入口版本和哈希。不要因解析器或 cwd 元数据修正而复制四次同一份快照及其整个历史 `validation/` 树；后续 attempt 引用同一快照哈希，只保存新命令、原始日志、差异和原因。收到的包可以原样保留，但旧包的历史验证不能作为新环境执行结果。

短路阻塞时，最小交付为当前状态 JSON、收到的路径/文件数、缺失项与恢复问题，以及实际执行过的检查。未启动工具就记录 not_run，不补做工具查询来填充报告。顶层入口指向当前状态，历史 attempt 另存。命令记录与清单使用相对产物路径，机器上实际执行过的绝对 cwd/安装路径照实保留。移机时修改的是新运行配置，不能改写旧日志或清单来掩盖路径变化。

归档计数区分“文件完整性已检查”和“设计验收通过”。文件哈希一致支持所列文件的完整性；skill 文件与预检日志不作为 RTL 设计测试。完整复制与重复副本的哈希不增加独立验证案例数。
